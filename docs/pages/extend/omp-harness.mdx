# Using the OMP Harness

Centaur can run [oh-my-pi](https://github.com/can1357/oh-my-pi) (OMP) as a
session harness alongside Codex, Claude Code, Amp, Nanocodex, Hermes, and Pi.
Select it with the `omp` harness type. The sandbox image installs OMP 18.8.6
with bun in the agent stage of `services/sandbox/Dockerfile` (`OMP_VERSION`),
because OMP's bin shim is a `#!/usr/bin/env bun` script.

The harness drives OMP through its long-lived JSONL protocol,
`omp --mode rpc --no-ui`. It starts one process per thread and reuses it across
turns: the first turn performs the handshake (`ready`, `negotiate_protocol` v2,
an event filter with delta message updates, `open_session`, an inherited
thinking level, cache warming off) and every later turn writes a `prompt` frame
to the same process. Startup waits up to 180 seconds for `ready`; handshake
commands time out after 30 seconds, and a prompt that OMP does not acknowledge
within 30 seconds fails the turn. Telemetry is left to the harness
(`OTEL_SDK_DISABLED`), so OMP does not export duplicate spans.

Steers (`steer_active_execution`) go to the running turn as OMP `steer`
commands. This holds in both wire modes: the blocks runner that production uses
routes a tagged message into the turn in flight instead of queueing it as the
next turn, and a tagged message that arrives while the session is idle starts a
turn as usual. Only OMP opts into that blocks-mode routing; the other shared
harnesses keep their previous queueing behavior. An interrupt sends OMP's
`abort`: when this abort's own result settles the turn within five seconds the
process and its session stay live, otherwise it is replaced. A failed steer or
abort ends the turn and replaces the process, because the run in flight can no
longer be steered; a rejected prompt keeps it.
A mid-run error — an extension failure or an error notice other than
`session-persistence` — fails the turn at the run's own settlement, so the rest
of that run never reaches the next turn; a `session-persistence` failure fails
the turn immediately and replaces the process. A turn runs for the execution's
`max_duration_ms` plus a short grace period (five minutes when unset), then is
aborted.

OMP's frames are bounded: a physical stdout line over 1 MiB (plus framing slack)
or a reassembled frame over 64 MiB (the ceiling OMP advertises in `ready`) fails
the turn instead of growing the server's memory. The 256-event queue
backpressures the reader instead of failing the turn.

OMP's stderr is never forwarded: it can carry provider responses and
authorization failures, so the harness drains it and logs only the byte count.

Earlier Centaur OMP integrations also stopped a run after 30 minutes without
output. That watchdog is intentionally gone: run length is bounded by the
execution's `max_duration_ms`, and a background run that stays quiet is allowed
to settle on its own rather than being killed.

## Harness architecture

`OmpHarness` plugs into Centaur's existing generic shared runner, which owns the
turn lifecycle: spawning and reusing the process, the turn loop, streaming and
telemetry to the client, turn completion, and process replacement. There is no
parallel OMP-specific lifecycle. OMP supplies hooks that adapt the protocol
(startup handshake, per-turn stdin frames, the JSONL event normalizer) and the
protections the generic runner applies only when a harness opts in: in-band
interrupt settlement, in-band blocks-mode steering, bounded stdout, prompt
acknowledgement, stderr redaction, and provider-per-turn process identity.
Harnesses that do not opt in keep their previous behavior, so these safeguards
are not universal.

The boundary runs where OMP's own semantics begin: session directories and
resume, model and provider selection, thinking levels, cache warming, builtin
slash commands, and background settlement are all OMP's. Centaur translates
what OMP reports into its wire items and forwards what the protocol carries; it
does not re-implement or second-guess OMP's agent behavior.

## Sessions

OMP saves each conversation in a per-thread directory named for the SHA-256 of
the Centaur thread key, under `CENTAUR_OMP_SESSION_ROOT` (default
`~/.omp/centaur-sessions`). Every process opens that directory, so a respawn
after an interrupt, model switch, or crash on the same sandbox resumes the same
conversation without a resume id. Only when the deployment gives the sandbox a
persistent state volume does the entrypoint symlink `~/.omp` at it, which is
what carries sessions across pod replacement; without such a volume sessions
live in the sandbox's ephemeral filesystem. An absolute
`CENTAUR_OMP_SESSION_ROOT` outside the state volume does not survive either.

## Slash commands

In RPC mode OMP decides for itself whether a prompt is a builtin command that
runs locally — which prompts count is OMP's choice, not a Centaur allowlist. The
harness forwards the prompt unchanged, and when OMP answers without invoking the
agent its `command_output` becomes the turn's reply. Output that arrives in a
turn OMP does invoke the agent for renders as a tool call instead.

## Models and credentials

The entrypoint copies `harness/omp/config.yml` and `harness/omp/models.yml` into
`~/.omp/agent`, substituting the LiteLLM gateway URL. They define a static
`litellm` provider keyed by `LITELLM_API_KEY` and the default model roles.
Subscription-backed roles authenticate through OMP's auth broker
(`OMP_AUTH_BROKER_URL`, `OMP_AUTH_BROKER_TOKEN`) when one is configured, and
otherwise fall back to the gateway.

`OMP_MODEL` names the thread's default model. A turn's `model` may be a bare
model id or `provider/modelId`: a qualified model opens the session on that
provider, a bare id keeps the provider the session restored or, when the blocks
protocol sends one, the turn's `provider` field. A rejected model fails that
turn and the next turn returns to the last working model. Because the model is
bound when the session opens, a turn naming a new model replaces the process
over the same session directory.

A turn's reasoning effort sets OMP's thinking level before the prompt
(`none`, `off`, `minimal`, `low`, `medium`, `high`, `xhigh`, or `max`); a turn
without one restores `inherit`, so a saved level from an earlier turn cannot
leak into it even though OMP persists the level in the session.

## Configuration

| Variable | Purpose |
|---|---|
| `OMP_MODEL` | Default model for a thread that names none (`modelId` or `provider/modelId`). When unset, the `default` role in `config.yml` applies. |
| `OMP_BIN` | OMP executable (default: `omp` on `PATH`). |
| `CENTAUR_OMP_SESSION_ROOT` | Root of the per-thread session directories (default: `~/.omp/centaur-sessions`). |
| `OMP_LITELLM_BASE_URL` | Gateway URL substituted into the baked config (default: `https://litellm.drkmttr.dev/v1`). |
| `CENTAUR_OVERLAY_OMP_DIR` | Directory whose `config.yml`/`models.yml` replace the baked copies file by file. The entrypoint waits up to `CENTAUR_OVERLAY_OMP_WAIT_SECONDS` (default `10`) for them to appear. |
| `PI_CODING_AGENT_DIR` | Overrides OMP's agent directory (default: `~/.omp/agent`). Pi reads the same variable, so setting it moves Pi's configuration too. |

Set these through `sandbox.extraEnv`.
